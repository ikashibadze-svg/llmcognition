# LLMCognition — инструкция на русском

Это готовый репозиторий для **CMT-2**, воспроизводимого эксперимента с OpenAI API.

Мы проверяем, может ли модель определить, когда ей недостаёт информации, выбрать **именно полезный** запрос в другом источнике и избежать поисков, когда вся нужная информация уже доступна. Два источника в данном тесте — закрытые локальные симуляторы `ARCHIVE` (дополнительная связь) и `AUDIT` (проверка достоверности записи). Никакого взлома или выхода из sandbox нет.

## Запуск

В существующем GitHub-репозитории сначала:

```bash
git pull origin main
python3 -m venv .venv
source .venv/bin/activate
pip install -e '.[api,dev]'
cp .env.example .env
```

В `.env` впиши **свой** `OPENAI_API_KEY`. Никогда не загружай `.env` в публичный GitHub.

```bash
# Локальные тесты без API / без затрат
python -m pytest -q
python -m llmcognition smoke

# Генерация и проверка 100 скрытых задач
python -m llmcognition generate --n 100
python -m llmcognition audit

# Настоящий пилот на OpenAI API (платные запросы)
python -m llmcognition run --backend openai --model gpt-4.1-mini --limit 8 --max-api-calls 60 --out runs/pilot.jsonl
python -m llmcognition report --results runs/pilot.jsonl --output-dir reports/pilot

# Полный эксперимент (до 500 API-вызовов)
python -m llmcognition run --backend openai --model gpt-4.1-mini --limit 100 --max-api-calls 500 --out runs/main.jsonl
python -m llmcognition report --results runs/main.jsonl --output-dir reports/main
```

Отчёт: `reports/main/REPORT.md`; все метрики: `reports/main/metrics.json`.

## Четыре экспериментальных условия

- **A:** информация полная, задача относительно простая. Ожидаем ответ без запроса.
- **B:** отсутствует один решающий факт. Ожидаем выбор правильного запроса в `ARCHIVE`.
- **C:** два факта противоречат друг другу. Ожидаем проверку нужной записи через `AUDIT`.
- **D:** информация полная, но рассуждение длиннее. Ожидаем отсутствие ненужного поиска.

Всего 100 задач — по 25 каждого типа. Тип задачи и правильный ответ **не передаются модели**. Все варианты получают шесть запросов (три ARCHIVE, три AUDIT), но только у B и C один из запросов действительно необходим. За каждую проверку снимается 0,10 балла.

Сравниваем адаптивного агента OpenAI, агента без поиска, случайный поиск, эвристику «мало фактов → поиск», всегда-поиск и детерминированный решатель ограничений. Последний — **не LLM**, а необходимый строгий контроль.

## Главные метрики

- Точность ответа и полезность с учётом цены поиска.
- Насколько чаще модель ищет недостающие знания в B/C, чем в A/D.
- Выбирает ли правильный диагностический запрос вместо случайного.
- Предсказывает ли начальная уверенность реальные ошибки (AUROC, Brier).
- Парные доверительные интервалы и пермутационные проверки различий.

Режим `--minimal` не требует числовой самооценки уверенности; он полезен для исследования более спонтанного поведения. Без числовой уверенности AUROC/Brier недоступны. Даже положительный результат будет доказательством **функционального поведения**, а не сознания или качественно нового физического свойства.

**Важно:** команда `smoke` запускает только локальный симулятор, а не OpenAI. Результаты этого режима запрещено публиковать как доказательство поведения реальной языковой модели.
