# CMT-2: диагностика пилота и восстановление .env.example

Этот архив — **дополнение**, а не замена существующего проекта. Он не меняет генератор задач, условия эксперимента, результаты или экспериментальные метрики. Содержит файл `.env.example` и скрипт `scripts/diagnose_pilot.py` (стандартная библиотека Python, **без API-запросов**).

Из корня репозитория `llmcognition`:

```bash
git pull origin main
unzip -o llmcognition_diagnostics_patch.zip -d .
python scripts/diagnose_pilot.py --results runs/pilot.jsonl
```

Если репозиторий запущен в Codespaces, проверь, что установленный ранее ключ доступен как переменная среды, не раскрывая его:

```bash
python -c 'import os; print("OPENAI_API_KEY available:", bool(os.getenv("OPENAI_API_KEY")))'
```

Если переменная среды уже задана, создавать `.env` **не обязательно**. Если нет:

```bash
cp .env.example .env
# В локальном .env впиши OPENAI_API_KEY; не публикуй секрет.
```

При копировании файлов команда вида `cp source/* destination/` пропускает файлы с именами, начинающимися с точки. Поэтому `.env.example` может отсутствовать после ручного переноса. Проверить содержимое исходного архива можно командой `unzip -l path/to/archive.zip`.

Для записи диагностического отчёта в приватную, исключённую из git папку:

```bash
python scripts/diagnose_pilot.py --results runs/pilot.jsonl --output reports/pilot/DIAGNOSTIC.md
```

Особенно важны четыре строки по A/B/C/D, доля диагностических запросов в B/C и индивидуальные действия `adaptive`. `0.0` — индекс, а не точность. `48 rows` означают `8 × 6` сравнительных политик, а не 48 независимых задач. Дальнейший вывод по метакогниции возможен только после изучения такого отчёта и более широкого теста.

**Не выкладывай** в публичный репозиторий `runs/`, `reports/`, `data/private/` или настоящий `.env`.
